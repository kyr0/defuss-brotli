Brotli compression in your browseron many CPU coreswith a ~50 KB decoderin Node.js and Bun

Compress and decompress Brotli in browsers, Node.js and Bun. The decoder is tiny, and the CLI compresses at least twice as fast as the official brotli CLI.*

Try it now See the numbers

* For files of 1 MiB and larger at quality 11, the default. Measured on an Apple M5 Max with 48 GB of RAM. The demo runs locally in this browser tab, without a server, and is still up to 5.3 times faster than the official brotli CLI.

bun add defuss-brotli
pnpm add defuss-brotli
npm install defuss-brotli
yarn add defuss-brotli

Or run it without installing

# writes dist/app.js.br, keeps dist/app.js
bunx defuss-brotli dist/app.js
# writes dist/app.js.br, keeps dist/app.js
pnpm dlx defuss-brotli dist/app.js
# writes dist/app.js.br, keeps dist/app.js
npx defuss-brotli dist/app.js
# writes dist/app.js.br, keeps dist/app.js
yarn dlx defuss-brotli dist/app.js

Multicore compression and command line implemented by Aron Homberg (kyr0) (opens in a new tab), open source (MIT (opens in a new tab))
Optimized WebAssembly build of dropbox/rust-brotli (opens in a new tab) · dropbox/rust-brotli-decompressor (opens in a new tab)

  • Brotli in the browser

    Chromium's built-in CompressionStream and DecompressionStream reject Brotli. defuss-brotli does both inside the page.

  • ~50 KB to decompress

    Pages that only decompress load just the decoder: ~50 KB when the server compresses it at Brotli quality 11, or 85 KB from jsDelivr. The compression code is never loaded.

  • Smaller than gzip

    Quality 11 is the default: 38 % smaller than gzip at its highest level on an HTML page, 27 % on JSON.

  • Multicore Brotli

    compressParallel spreads large inputs over your CPU cores: 100 MiB at quality 11 takes 17 s on 13 cores instead of 139 s on one, and the output is at most 0.1 % larger.

  • Little memory

    Data passes through in 1 MiB pieces. Unpacking 100 MiB, the decoder uses ~20 MiB of RAM.

  • Faster than the brotli CLI

    bunx defuss-brotli accepts the options of the brotli command and is 1.2 to 5.3 times faster than the official brotli CLI on files of 256 KiB and larger.

        How it works
        
§Two packages in one, split where it pays

        
The encoder and the decoder are separate Rust libraries compiled to separate WebAssembly files. Pages that only decompress load only the decoder.

      

    

    
    
    
      
  • 
        
    Separate downloads
    
        
    The decoder is a ~50 KB download, the encoder 397 KB. Build tools leave the encoder out of apps that only decompress.
    
      
    • 
      
  • 
        
    Memory stays flat
    
        
    Data passes through 1 MiB at a time, so memory does not grow with the input: unpacking 100 MiB takes ~20 MiB.
    
      
    • 
      
  • 
        
    Same bytes on any machine
    
        
    Where the input is split depends only on its length and the settings, never on the cores, so any number of cores produces the same file, byte for byte.

          Use it
          
§A few lines in your app, or one command

        

      

      

        

          
In code

          

            

              
              
              
            

            

              
Loads only the decoder, then decodes a file your server stored as Brotli.

              
import { init, decompressText } from "defuss-brotli/decompressor/slim";
 
await init(); // fetches decompressor.wasm
const response = await fetch("/data/catalog.json.br");
const bytes = new Uint8Array(await response.arrayBuffer());
const catalog = JSON.parse(decompressText(bytes));

            

            

              
Precompresses build output at quality 11 on all cores.

              
import { readFile, writeFile } from "node:fs/promises";
import { init, compressParallel } from "defuss-brotli/compressor";
 
await init();
const input = await readFile("dist/app.js");
await writeFile("dist/app.js.br", await compressParallel(input));

            

            

              
An import map that points at jsDelivr; the decoder fetches its .wasm from the same folder.

              
<script type="importmap">
  { "imports": { "defuss-brotli/decompressor/slim":
    "https://cdn.jsdelivr.net/npm/defuss-brotli@0.4.0/dist/decompressor-slim.js" } }
</script>
<script type="module">
  import { init, decompress } from "defuss-brotli/decompressor/slim";
  await init();
</script>

            

          

        

        

          
On the command line

          
Same options, defaults and output names as the brotli CLI, so build scripts can swap it in.

          

            
            
            
            
          

          
# writes dist/app.js.br and keeps dist/app.js
bunx defuss-brotli compress dist/app.js
# several files, quality 11 by default
bunx defuss-brotli -v dist/*.html dist/*.css
# decompress to standard output
bunx defuss-brotli -d -c data.json.br | head
# writes dist/app.js.br and keeps dist/app.js
pnpm dlx defuss-brotli compress dist/app.js
